## Design Context
### Users
Learners and educators use the browser robotics workbench primarily on 15-inch laptops. First-time learners need guidance, while advanced learners need direct, efficient access to real physical-style Python and generated Blockly Python. Their job is to select a robot/task, understand constraints, write or inspect code, run and control it, observe contact and motion, diagnose failures, and transfer the source pattern to physical hardware.
### Brand Personality
Trustworthy, clear, technical, educational, and calm. It should build confidence without pretending the simulation is more physically predictive than it is.
### Aesthetic Direction
Preserve and refine the existing technical workbench visual language; do not conduct a gratuitous rebrand. The 3D scene, code, task requirements, execution status, and recovery controls need a deliberate information hierarchy. Avoid generic AI dashboard styling, ornamental cards, neon/glass effects, visual clutter, and game-like claims.
### Design Principles
1. Visible physical behavior and authoritative state must agree.
2. Code, current task, execution state, and next corrective action remain discoverable without memory-heavy navigation.
3. One clear primary action per state, with immediate status and actionable error recovery.
4. Preserve learner work and provide explicit Run, Pause, STOP, Reset, camera reset, and source export affordances.
5. Accessibility, keyboard use, readable contrast, and 15-inch laptop fit are baseline quality, not optional polish.
